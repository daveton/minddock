# MindDock 可行性分析（以“用户体验第一 + 本地存储优先”为硬约束）

## 1. 结论（先说结论）

在当前目标范围内，**项目可行且建议继续推进**，前提是严格执行以下两条不妥协原则：

1. **输入路径与数据/网络路径物理隔离**（输入链路绝不阻塞）。
2. **本地单机体验先闭环，再做同步**（同步是增强层，不是主路径）。

若按现有文档的分阶段策略执行，Phase 1 可在较低复杂度下验证核心价值（“无摩擦写作”）。

---

## 2. 可行性拆解

## 2.1 产品可行性

- 目标用户痛点明确：需要快速、低干扰、离线可用的写作系统。
- 差异化明确：不做“全能知识库”，而是把输入体验做到极致。
- MVP 可验证：仅靠“编辑 + 自动保存 + 崩溃恢复”就能验证核心体验价值。

结论：**产品方向可行**。

## 2.2 技术可行性

- TipTap/ProseMirror 适合作为实时编辑内核。
- IndexedDB 足以支撑本地笔记存储与恢复。
- Repository 抽象可为后续同步留出演进空间。

关键难点不在“能不能做”，而在“能否持续守住性能边界”。

结论：**技术实现可行，但对工程纪律要求高**。

## 2.3 交付可行性

- Phase 1 范围小，依赖少，适合快速落地。
- Phase 2（标签+搜索）复杂度中等，可在本地继续闭环。
- Phase 3（同步）风险最高，应在前两阶段稳定后进入。

结论：**按阶段推进可行，禁止跨阶段并行堆功能**。

---

## 3. 硬约束落地为“工程红线”

## 3.1 用户体验第一（输入路径红线）

输入阶段（keydown → transaction）禁止：

- 访问 IndexedDB
- 调用 Repository
- React/Zustand setState
- Markdown 同步解析
- 任意网络请求

输入阶段允许：

- TipTap transaction
- 最小 DOM patch

## 3.2 本地存储优先（数据路径红线）

- 所有写操作先落本地。
- 读取优先本地缓存。
- 同步失败不得影响本地编辑。
- 离线模式必须全功能可用（除云同步本身）。

---

## 4. 架构建议（面向实施）

采用“双通道架构”：

1. **实时通道（高优先级）**：Editor 内部事务，仅处理输入与渲染。
2. **后台通道（低优先级）**：保存、索引、标签解析、同步队列。

调度策略：

- onUpdate 只采集最小变更信号；
- `debounce(300ms)` 执行持久化；
- 非关键任务（搜索索引、标签解析）走 `requestIdleCallback`。

---

## 5. 风险与缓解

| 风险 | 触发点 | 影响 | 缓解策略 |
|---|---|---|---|
| 输入卡顿 | onUpdate 中做重计算 | 直接破坏核心体验 | 输入阶段零重计算；性能监控 + 代码审查红线 |
| 数据丢失 | 崩溃/意外刷新 | 信任受损 | debounce 保存 + 页面隐藏时强制 flush |
| 状态污染 | UI 状态耦合编辑器状态 | 光标跳动/渲染抖动 | 编辑器状态与 UI 状态严格分层 |
| 同步拖慢本地 | 同步逻辑侵入主链路 | 本地体验退化 | 同步仅消费本地变更队列，不反向阻塞输入 |
| 范围失控 | 过早加 AI/插件 | 交付延迟 | 里程碑 gate：性能验收未过不得扩功能 |

---

## 6. 验收指标（按阶段）

## Phase 1（必须）

- 输入延迟 p95 < 16ms
- 笔记打开时间 p95 < 100ms
- 连续输入 10 分钟无明显卡顿
- 刷新/崩溃后内容可恢复
- 离线状态可创建、编辑、删除笔记

## Phase 2（新增）

- 标签解析后台执行，不影响输入帧时间
- 搜索结果首屏响应 < 150ms（本地数据量 5k 笔记以内）

## Phase 3（新增）

- 断网可持续编辑
- 网络恢复后自动补同步
- 同步失败不阻塞本地读写

---

## 7. 执行优先级（建议）

1. 先完成 Phase 1 的“体验闭环 + 监控埋点”。
2. 再做 Phase 2 的组织能力（标签/搜索）。
3. 最后做 Phase 3 的同步与部署。

推进规则：**任何阶段若核心性能指标不达标，立即停止扩功能并回归性能修复**。



## 8. 指标测量基线（新增）

为避免“主观流畅”，所有性能指标需要统一口径：

- 采样环境：同一设备、同一浏览器版本
- 输入延迟：`keydown` 到 transaction 完成
- 打开耗时：点击 note 到可编辑状态
- 统计方式：至少 30 次样本，取 p95

若不满足统一口径，则该轮性能结论无效。
